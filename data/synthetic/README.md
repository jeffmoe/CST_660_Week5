# Synthetic core-banking dataset

Generated by `scripts/generate_synthetic_data.py` (seed 660, deterministic with the pinned versions in `requirements.txt`).
Covers the 90 days 2026-07-03 through 2026-09-30 for 42 branches. `manifest.json`
lists exact row counts and every injected defect by ID.

| File | Grain | Rows | Key |
|---|---|---|---|
| `branch_reference.csv` | one row per branch (intended) | 43 | `branch_code` |
| `customers.csv` | one row per customer | 1,450 | `customer_id` |
| `accounts.csv` | one row per account (intended) | 2,003 | `account_id` |
| `daily_balances.csv` | one row per account per day while open | 173,313 | `account_id`, `balance_date` |

Relationships: `accounts.customer_id → customers.customer_id`,
`accounts.branch_code → branch_reference.branch_code`,
`customers.home_branch_code → branch_reference.branch_code`,
`daily_balances.account_id → accounts.account_id`.

## Injected defects

These are deliberate. They are the failure classes the quality gates must catch.

| Defect | Table | Count |
|---|---|---|
| Duplicate `account_id` (1 exact double-load, 2 with conflicting branch/product) | accounts | 3 IDs, 3 extra rows |
| `branch_code` not in branch_reference (`BR043` ×2, `BR099`, `BR000`, `BR7`) | accounts | 5 |
| Null `customer_id` | accounts | 4 |
| Duplicate `branch_code` key: `BR017` appears twice (region re-org row never retired) | branch_reference | 1 extra row |
| Decimal-shift spike: one day's ledger and available balance posted ×100 | daily_balances | 1 row |

The `BR017` duplicate reproduces last quarter's incident: joining balances to
`branch_reference` on `branch_code` doubles every BR017 account (57 rows), which
inflates 2026-09-30 total deposits by about $1.37M (~3.8%). No row is lost and
nothing errors, so the overstatement is silent.

Checking accounts keep a cushion of 40–100% of a paycheck (topped up by a sweep
from savings), so they do not sit at $0 between paydays.

Everything else is clean: `daily_balances` has no orphan accounts and no duplicate
`(account_id, balance_date)` pairs, and every non-null `customer_id` resolves.

Built with numpy (vectorised RNG and balance simulation), pandas (frames and CSV
output) and Faker (customer names). To regenerate:

```
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python scripts/generate_synthetic_data.py
```

Pass `--clean` for a defect-free copy, or `--out <dir>` to write elsewhere.
